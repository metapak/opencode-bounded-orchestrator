# Usage report and local evaluation

`usage_report.py` normalizes observed display rows from `opencode stats`. The official CLI has no `stats --json` option. Input/output/cache counts ending in K/M are marked rounded; missing counters remain unavailable. `--days` and `--project` use the CLI's supported filters. An explicitly chosen `--session ses_…` uses `opencode export SESSION --sanitize`, keeping only safe identifiers and token counters; no chat bodies or titles are shown. The browser's model chart instead uses exact observed counters from at most 12 recent sanitized session exports; a missing model is Unknown. The orchestra identifies helpers by linked child-session ID, not by a role or model label. Its distinct characters reflect observed duty metadata, while Setup shows planned slots. A working style breakdown is an estimate only for conservatively matched local settings history. `--fixture` accepts an export-shaped test record and labels it DEMO. Missing CLI, command failure, timeout or unrecognized output returns `unavailable` and a nonzero exit. No inferred cost, quota, savings, live activity or subscription mapping is produced. See [local browser console and verified source contracts](local-console.md).

`local_eval.py` accepts an explicit JSON manifest containing `label`, `argv`, and a bounded timeout. It uses `shell=False`, stores hashes and optional sanitized tail only, and fingerprints the Git candidate before and after the command. A changed candidate becomes `candidate_changed`. Ledger readiness rejects missing, failed, or stale required evaluation.
